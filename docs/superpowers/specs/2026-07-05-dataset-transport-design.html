Data-to-data transport datasets
CIFAR cat→dog & AFHQ cat→dog

2026-07-05 · diffusion-bridge draft — awaiting review

Goal

Extend the bridge-diffusion library so the Gaussian bridge can be trained as a data-to-data transport between two image distributions, and add two concrete experiments:

  1. CIFAR-10 cat→dog at 32×32 — cheap stepping stone, runs locally.
  2. AFHQ cat→dog at 64×64 — headline transport experiment, matching the benchmark used by Rectified Flow / DSBM / DDBM.

Deliverable includes runnable configs and a step-by-step training guide.

Non-goals

  • Poisson-bridge transport (the integer bridge stays noise→data on MNIST).
  • CelebA or ImageNet support.
  • Non-independent couplings (OT minibatch coupling, reflow). The paired loader samples source and target independently — the standard first-pass coupling in the literature. The design leaves room to add couplings later.

Background: what the code already supports

The maths is already general. BridgeDiffusion.compute_training_loss(x, y) never assumes a Gaussian prior, and the sampler already accepts arbitrary start points x0. The only place noise is hardcoded is the trainer: y = batch[0], x = randn_like(y) (training/trainer.py:24-39, 210-214).

So the work is: dataset entries, a paired loader, one trainer branch, configs, and sampling/evaluation plumbing for source-conditioned generation.

Design

1 · Config (config/config.py)

Extend DataConfig with flat, backwards-compatible fields:

@dataclass
class DataConfig:
    dataset: Literal["mnist", "cifar10", "afhq"] = "mnist"   # target distribution
    classes: list[str] | None = None          # filter target to these classes
    source_dataset: Literal["mnist", "cifar10", "afhq"] | None = None
    source_classes: list[str] | None = None   # filter source to these classes
    # ... existing fields unchanged (data_dir, image_size, num_workers, ...)

Transport mode is active iff source_dataset is not None. All existing configs remain valid with unchanged behaviour; from_yaml needs no structural change. Validation: source_classes without source_dataset is an error; class names are validated at load time (fail fast, listing valid names).

2 · Data loading (data/datasets.py)

AFHQ entry. torchvision ImageFolder rooted at {data_dir}/afhq/train and …/val (subfolders cat/ dog/ wild/). Missing directory → error pointing at scripts/download_afhq.sh. Transforms: Resize → CenterCrop → RandomHorizontalFlip (train only) → ToTensor → Normalize to [-1, 1]. AFHQ sources are 512×512, so the resize path also covers 32×32 smoke runs.

Class filtering. filter_classes(dataset, class_names) → Subset, working for both CIFAR10 (classes/targets) and ImageFolder (class_to_idx/samples). Unknown names raise ValueError listing valid options.

Paired dataset.

class PairedDataset(Dataset):
    """Independent coupling of a source and a target dataset.

    __len__ = len(target). __getitem__(i) returns (x_source, y_target) where
    y_target is item i and x_source is drawn uniformly at random (torch.randint,
    so per-worker seeding behaves under num_workers > 0). Labels are dropped.
    """

get_dataloader builds the target dataset as today; with a source configured it builds the (filtered) source dataset too and wraps both in PairedDataset. get_data_info gains an AFHQ branch (3 channels; train: cat 5153 / dog 4739 / wild 4738; val ≈ 500 per class) and reports filtered sizes when classes is set.

3 · Trainer (training/trainer.py)

One branch keyed off config, not tensor-shape guessing:

if self.transport:            # config.data.source_dataset is not None
    x, y = batch[0].to(device), batch[1].to(device)
else:
    y = batch[0].to(device)
    x = _sample_prior(self.model, y)
loss = self.model.compute_training_loss(x, y)

In transport mode _log_samples starts the sampler from a fixed batch of held-out source (val) images, so MLflow sample grids show actual cat→dog translations during training.

4 · Sampling and evaluation

  • cli.py sample gains --source-dir PATH (folder of images used as x0, eval transform). Omitted in transport mode → falls back to the val split of the configured source dataset. Noise fallback remains for non-transport checkpoints. Generated images keep their source filenames so translations are inspectable pairwise.
  • FID mechanically unchanged. A helper scripts/export_val_images.py dumps a dataset/class val split to PNGs (needed once to build the real-dog reference folder).

5 · AFHQ download (scripts/download_afhq.sh)

Fetches the official AFHQ release used by stargan-v2 (Dropbox zip, ~500 MB), unzips to data/afhq/{train,val}/{cat,dog,wild}, prints counts. URL pinned in the script with fallback notes (Kaggle mirror / HuggingFace huggan/AFHQ).

Verify the Dropbox link at implementation time — it occasionally moves.

AFHQ 64×64 UNet: block_out_channels (128, 256, 384, 512), 2 layers per block, attention in the two lowest-resolution blocks, EMA 0.9999, lr 1e-4. Bridge params (T, eps) start from CIFAR values; tuning T for transport is an open experimental question, not fixed here.

7 · Testing

  • tests/test_data.py: filter_classes on CIFAR-10 and a tmpdir ImageFolder; PairedDataset length/shapes/value range/label dropping; config round-trip with new fields; validation errors (unknown class, source_classes without source_dataset).
  • Trainer transport branch smoke test: tiny synthetic ImageFolder pair, a few steps, loss finite.
  • Smoke configs double as end-to-end tests: train → sample → evaluate on ~200 steps.

8 · Error handling

  • Missing AFHQ data dir → actionable error naming the download script.
  • Unknown dataset/class names → ValueError listing valid options.
  • sample --source-dir on a non-transport checkpoint → warning, proceeds (mathematically fine; the model just wasn't trained for it).

What you need to do to train

  1. Smoke test locally (MPS, minutes): 
    uv run bridge-diffusion train --config configs/cifar_cat2dog_smoke.yaml
uv run bridge-diffusion train --config configs/afhq_cat2dog_smoke.yaml  # needs AFHQ downloaded
  2. CIFAR cat→dog for real (local; overnight on MPS or ~2–3 h on one GPU): 
    uv run bridge-diffusion train --config configs/cifar_cat2dog.yaml
  3. AFHQ (needs a CUDA GPU; roughly 1–2 days on a single A100/4090 at 150k steps): 
    bash scripts/download_afhq.sh
uv run bridge-diffusion train --config configs/afhq_cat2dog_64.yaml
  4. Sample translations and evaluate: 
    uv run bridge-diffusion sample --checkpoint outputs/.../model.pt --num-steps 100 --use-ema
uv run python scripts/export_val_images.py --dataset afhq --classes dog --out data/fid_ref/afhq_dog
uv run bridge-diffusion evaluate --real-dir data/fid_ref/afhq_dog --generated-dir outputs/samples
  5. Monitor via MLflow as today — sample grids will show cat→dog translations.

Open questions deferred to experiment time

  • Best bridge terminal time T for transport (start with CIFAR value, sweep).
  • Whether AFHQ FID is reported against val dogs only (standard) or train+val — follow DDBM's protocol when writing the paper section.
